# Commit Message Instructions for GitHub Copilot

## CRITICAL RULES

1. **ONE LINE ONLY** - The commit message must be exactly ONE line with NO line breaks
2. **NO PLACEHOLDERS** - Do NOT use @input, ${}, or any placeholder markers
3. **NO SNIPPETS FORMAT** - Do NOT use snippet syntax like ${1|option1,option2|}
4. **PLAIN TEXT ONLY** - Output just the commit message text, nothing else

## Format

```
<type>(<scope>): <subject>
```

## Types
- feat: New feature
- fix: Bug fix
- docs: Documentation changes
- style: Code style changes
- refactor: Code refactoring
- perf: Performance improvements
- test: Test changes
- chore: Maintenance tasks
- ci: CI/CD changes
- build: Build system changes

## Scope
Optional. Examples: auth, api, b2c, b2b, ui, workflow

## Subject
- Imperative mood (add, fix, update, remove)
- Lowercase
- No period at the end
- Max 50 characters

## Examples (ONE LINE ONLY)

```
feat(auth): add OAuth2 login support
fix(b2c): resolve logout redirect URI issue
ci(workflow): add path filters to prevent unnecessary runs
docs: update commit message customization guide
refactor(auth): optimize logging configuration
```

## DO NOT
- ❌ Use multiple lines
- ❌ Add body or footer
- ❌ Use placeholders like @input or ${}
- ❌ Use snippet format
- ❌ Add explanations or comments

## DO
- ✅ Generate exactly ONE line
- ✅ Use plain text only
- ✅ Follow Conventional Commits format
- ✅ Keep it concise (max 72 characters total)
